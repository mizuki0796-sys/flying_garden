读取微信附件中的 66 条规则和 13 条填写意见，结构化原文保存在 [review-2026-11-05.json](review-2026-11-05.json)。附件是设计资料，不执行其中的脚本或操作指示。采用填写意见覆盖旧草案，特别是炮兵默认自动攻击、整个世界暂停、离开战斗视角继续战斗、毁营后失控且士气下降、原地重建恢复。

## 操作

1. 主游戏开始试玩后按 **F8**；或直接运行独立战斗场景。
2. 选择 1–4 队。建原属帐篷，升级训练营（1～4 级依次解锁盾卫、剑士、弓手、炮兵），点击训练。单队最多 4 名额；炮组占 2 名额。训练完成后再点可继续补员。
3. 切探索船，WASD 靠近敌岛左岸，点击侦察。切运兵船，驾驶至对应编号营位附近，建营。
4. 驾船回主岛码头，点“装卸本队”；再开至对应前线营地，点“装卸本队”登陆。一次运一队，重复可部署四队。
5. 炮兵需要事先“制弹 +1”。切战术镜头，点红色 Boss / 敌军驻地宣战。准备期只允许沿岸活动。
6. 数字 1～4 选队，选进攻/守住后左键指定地点；WASD 平移镜头。炮兵默认自动射击；接管后每次左键只发一轮，恢复自动后重新自行选敌。空格全世界暂停，暂停时可选队、移镜头、下令，扣费与执行留到恢复后。
7. “撤离本队”命令队伍回对应营地，运兵船靠近才能接走；再手动驾驶回主岛卸下。战斗中可在船靠近时拆营，失营队伍失控、伤害降低至 25%、移动减半；原位重建可恢复指挥。
8. “回到主岛”或 F8 返回经营，战场继续模拟；F8 重返。如果离开时暂停，空格恢复。侧栏可滚动，底部可重开 30/100/300 格测试；重开会清空本次测试状态。

独立场景的“回到主岛”只切回测试码头观察；通过主游戏 F8 打开的版本返回实际经营操作。

| 炮击 | 每门 20 秒独立冷却，1 发 + 8 E，溅射半径 85，无友伤；移动中不能开火 |
| 炮弹 | 4 石 + 2 矿；测试仓库共享，不做实体货舱 |

单位距离和速度均为原型世界像素及像素/秒。普通兵每秒攻击一次，盾卫简化为全向减伤 50%。每名基础兵单独扣血；炮组作为一个双人整体损失。营地被毁不直接杀死士兵。失败后可用重开按钮再测，未做持久战役。

## UI 制作任务单

- 用户要求：可操作，UI 暂用占位符。
- 视觉母版：不修改现有位图，无新增位图素材；新场景只用色块、圆点、文字和 Godot 默认按钮。
- 允许变化：战斗测试侧栏、战场标记、镜头与指令反馈，主游戏 F8 入口及相应输入隔离。
- 保持：已有建筑、飞轮、烟雾、船体素材及绘制逻辑；不新增机械动画。
- 参数：地块 80×64；窗口 1152×648；镜头缩放 0.9。无额外光效、抖动或烟雾。
- 验证：预览实例化真实 `main.gd` 与 `landing_battle_ui.gd`，不另画展示版本；原有素材文件不修改，运行原游戏冒烟检查。
- 交付：原型代码、场景、测试、截图、性能 JSON。本次没有位图生成、拆图或动画视频。

## 验证与限制

运行 `godot --headless --path game --script res://tests/landing_battle_test.gd` 验证训练、运输、暂停、炮击、士气恢复及结算。`landing_battle_preview.gd` 检查主游戏输入隔离、全局暂停、后台战斗，并在图形模式下生成 100/300 格截图和性能数据，输出到 `artifacts/game/landing-battle/`。原游戏 `smoke_test.gd` 也应通过。

性能测试使用真实主游戏绘制和占位战场；固定满员部署，每场景 240 帧，经营物理模拟停止，故只能评估该原型，不能代表最终美术和全部系统同时运行的性能。需结合 `report.json` 的 GPU 与 P95 数据，不以无窗口逻辑测试声称稳定帧率。

尚未接入：主世界敌岛生成、实际探索船/运兵船建造、经营建筑与科技树、正式资源池、主岛巡逻、障碍寻路/单位碰撞、方向盾防、炮组单人伤亡与火炮回收、船毁救援、矿藏解锁、补血、战争存档及多战场。测试中的探索船和运兵船是独立标记，不能与原采矿船混淆。存档菜单仍只保存原经营游戏，退出程序会丢失测试战斗。
